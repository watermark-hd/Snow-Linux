# 計画

## 決定事項

- デスクトップは **Xfce** (軽さは譲れない。KDE は使わない)
- x86_64 版も PPC 版も同じ Xfce → テーマ・設定・自作ツールはすべて共通
- 目標: 往年の Mac を使ってきた人が違和感なく使える完成度。足りない部分はコードを書いてでも埋める
- アニメーションは控えめ (ジニー・Dock の跳ねは不要)。写真の現像・書き出しに集中できる、余計な動きのない Mac が理想
- **いちばん大事な原則: 普段の操作は極限までキビキビさせる。** マウスが遅れない、アプリを開くのに何分も待たない。書き出しやフィルターにかかる時間は機械の性能次第でよい
  - 目的: 古い機械でも、写真の編集 → 書き出し → サイズ調整 → プリントの流れを快適にする
- **リリースの順序: まず x86_64 版を出す。** PPC 版のリリースは絶対条件だが、先に目標となる完成品が必要なため後に回す。共通部分 (themes / config / assets) はアーキテクチャに依存しないように作り続ける
- 写真アプリは既存の軽いものを採用する方向 (候補: PhotoCraft、LightCraft)。独自の写真アプリは作らない
- 名前: 「Snow Leopard」は説明文での言及にとどめる。商標を避けるため、将来の改名も選択肢として残す

## 絶対条件

- Mac OS X 10.4 (Tiger) 〜 10.6 (Snow Leopard) を使っていた人が違和感なく操作できること
- 「ちょっと懐かしい」と思えること
- 本家そっくりにする。「ここの再現性がいまいちだな」と思わせない
- ただし、使いやすくなるなら思い切って機能を入れる
- Linux 独自のアプリは迷いの元なので、余分なものはすべて消す。オフィスと写真関連は充実させる
- 管理アプリ (システム環境設定) もほぼ同じにする
- Finder の内容まで再現する (アプリケーションフォルダ、ゴミ箱など)

方針メモ:

- 「そっくり」は配置・操作・挙動・雰囲気を指す。素材 (アイコン・壁紙・フォント・ロゴ) は自作で、Apple のものは使わない (下の「注意」と同じ)
- 余分なアプリを消すとき、設定やシステム管理に必要なものは消さずに、システム環境設定の中にまとめて隠す

## 使用目的

集中すること:

- ネット閲覧、YouTube
- 写真の閲覧と整理
- ちょっとした写真編集、少し本格的な写真編集
- ちょっとした仕事の書類作り (オフィス)

目指さないもの: ゲーム、音楽編集。プログラミングは目的ではないが、どの Linux でもできるので、VS Code は標準で入れる。

- 軽量で、古い PC でもキビキビ動く。アプリの起動が早い (いちばん大事な原則と同じ)
- 標準で入れるアプリは上の目的に絞る。オフィスと写真関連は充実させる
- MX Tools など Linux の便利な管理ツールは、アプリケーションフォルダの中の「ユーティリティ」フォルダにひととおり入れる (Mac の /Applications/Utilities と同じ位置づけ)。普段の画面には出さない

## テーマの選択肢

- 基本は Snow Leopard 調
- **Tiger 調のメタルウィンドウも選べるようにする** (xfwm4 テーマ + GTK テーマ。設定画面から切り替え)

## ディスプレイ調整アプリ (自作・必須)

- 目的: 測色器 (キャリブレーター) なしで、ディスプレイの色を簡易的に調整できる小アプリ。x86 機のモニターは色がまちまちで、そのままでは写真を見るのに向かない。Mac に寄せるには GUI で調整できることが必要
- 形: Mac の「ColorSync」/「ディスプレイの色調整アシスタント」のように、画面を見ながら調整して **ICC プロファイルを作れる**こと
- 方式: Mac の「ディスプレイの色調整アシスタント」(エキスパートモード) と同じ。四角い枠の中のリンゴを、背景の模様と同じに見えるまでスライダーで合わせる
  - 背景は黒と色を 1 ピクセルごとの縞にしたもの (光の量はちょうど半分)。リンゴは単色のベタ塗り。リンゴの値を動かして縞と同じ明るさに見える点を探す
  - 本家は「中間色」と「シャドー」の 2 段階 × R・G・B = 6 回。SnowLinux では **中間色とハイライトの間の段階を足して、3 段階 × R・G・B = 9 点**にする (案: 約 25% / 50% / 75%)。各色の特性曲線を求めて補完し、ICC プロファイルとガンマ補正にする
  - 理由: 肌色 (子どもの写真など) は中間色からハイライト寄りの階調と RGB のバランスで見え方が決まる。この範囲は点を増やして正確にする
  - 元写真家のこだわり: 肌色は **G を引く → マゼンタを少し → B → 最後に R をほんの少し足す**、の順で整えると、いつも見ている自然な肌色になる。この順番は、ケータイのアプリよりも自然に仕上がる (YMCK の調整では難しい)
  - この順番を、調整の流れ (段階の順序、補完で重く見る色) に取り入れる。RGB のスライダーで直接調整するこのアプリの方式だからできること
  - 段階の順序や、肌色の確認用の画面を入れるかどうかは、試作しながら決める
  - 目視で測るのは「同じ明るさに見えるか」だけ。測色器は要らない
  - 縞は 1 ピクセル単位で正確に描く。全画面で、拡大やコンポジター (影・透過) を通さない
  - 正面から見て、少し目を細めて合わせるよう案内する (液晶は角度で明るさが変わる)
- 分かるのはガンマと RGB のバランス (白色点) まで。原色は sRGB を前提にする。この限界は説明に書く
- 実現方法の案 (要検証):
  - 調整値を ICC プロファイル (ガンマ曲線 / vcgt) として書き出す (lcms2 などで生成)
  - ログイン時に自動で読み込む (X11 のガンマ調整 / colord など)
  - GUI は GTK3 の小アプリ。常駐させない (軽さのため)
- 限界: 目視の調整なので、測色器を使った校正ほどの正確さはない。「簡易的に整える」ものとして説明する
- 写真アプリ (darktable など) が同じプロファイルを使えるようにする

## 標準アプリの確認事項

- VS Code は Microsoft のライセンス上、ISO への同梱が許されるか要確認。難しければ、初回起動時に導入する方法か、VSCodium を検討する

## 写真アプリの確認事項

- PhotoCraft / LightCraft は deb で配布されている (ユーザー確認)
- ライセンスは GitHub で確認した (2026-11-01): **PhotoCraft も LightCraft も Apache-2.0**。ライセンス表示 (NOTICE) を付ければ ISO に同梱できる
- 本家は `storytold/photocraft`、`storytold/lightcraft` (Rust 製、開発は活発で、数日おきにリリース)。PhotoCraft は Photoshop 風の画像編集、LightCraft は Lightroom 風の現像と管理
- 配布形式: x86_64 の deb、AppImage、Flatpak など。**PowerPC 用のビルドはない** → PPC 版には別の方法が必要 (ソースからのビルド、または別のアプリ)
- 気をつける点: ① 実行ファイルが約 130MB と大きい (起動の速さを測る)。② GTK ではなく独自の描画 (Vulkan / EGL を使う) → 古い GPU でどう動くか、見た目の統一 ③ まだ初期段階

## 差別化 (PearOS との比較)

PearOS (2025 年に Arch + KDE Plasma 6 で復活。最新の macOS 風。Apple に近い素材。未完成の機能あり。インストーラーはドライブ全体のみ) とは対象が重ならない。

| | PearOS | SnowLinux |
|---|---|---|
| 目指す姿 | 最新の macOS | Snow Leopard の操作感 |
| 対象の機械 | 比較的新しい PC | 古い機械 (PPC Mac も含む) |
| デスクトップ | KDE Plasma | Xfce |
| 土台 | Arch (ローリング) | MX Linux / Debian (安定) |
| 素材 | Apple に近いものを使う | 自作のみ |

SnowLinux の強み:

1. 古い機械でのキビキビ感 (上の原則)
2. 写真の流れ (現像 → 書き出し → サイズ調整 → プリント) に集中できる
3. PPC Mac で動く現行カーネルの Linux (ほぼ空白の領域)

守ること:

- 未完成の機能は出さない。ボタンを置くなら動かす
- インストーラーは「ドライブ全体を消す」だけにしない。データを残したい人が多い
- Apple の素材と名前を使わない

## キビキビさせるための方針 (案)

| 問題 | 対策の案 |
|---|---|
| 書き出し中にマウスや他の操作が止まる | 重い処理 (書き出し・一括変換・サムネイル作成) は優先度を下げて動かす (nice / ionice)。カーネルは操作を優先する設定にする |
| メモリ不足で固まる (G4 は 512MB〜1GB) | zram (メモリを圧縮して使う) を使い、遅い HDD へのスワップを避ける。足りなくなったら固まる前に重いアプリだけ止める (earlyoom) |
| 古い HDD が遅い | 起動時のサービスを減らす。HDD 向けの I/O スケジューラー (bfq) で操作を優先する |
| 写真の多いフォルダを開くとサムネイル作成で重くなる | サムネイル作成は優先度を下げる。RAW は中に入っている JPEG のプレビューを使い、RAW 本体は読まない |
| 画面の描画が重い | PPC では影や透過を切った軽いテーマを使う。コンポジター (picom) は最小限にするか切る |
| 写真用のアプリが重い | 軽いアプリを標準にする。サイズ調整や一括書き出しは libvips を使う (速くてメモリが少なくて済む)。プリントは CUPS + Gutenprint |

- 目標の数字を決めて、PPC の機械と安いノートパソコンで測る (例: アプリが数秒で開く、書き出し中でもマウスが滑らか)

| Snow Leopard の操作 | 実現方法 |

## Finder (ファイルマネージャー) の方針

見た目は Finder にかなり近づける。ただし Windows に慣れた人も多いので、戸惑いやすいところは選べるようにする。

| 項目 | 選べるもの | 実現方法 |
|---|---|---|
| 閉じる・最小化ボタンの位置 | 左 (Mac 風) / 右 (Windows 風) | xfwm4 の `button_layout` + GTK の `decoration-layout` (設定だけなので重さは変わらない) |
| 左のバー | Mac 風 (デバイス・ユーザーフォルダ・よく使う場所) / Windows 風のツリー | Thunar の標準機能 (ShortcutsPane / TreePane)。初期のブックマークは `config/` で用意 |
| ファイルの表示 | アイコン / 一覧 / カラム | アイコンと一覧は Thunar の標準機能。カラム表示は Thunar に追加する (自作) |

### 最初の起動時の質問

最初の起動時に「Mac と Windows のどちらに慣れていますか?」と聞き、ボタンの位置・左のバー・キー操作をまとめて設定する。あとの変更は Mac 風の設定画面で各自が調整する。

| 機械 | 最初の起動時 |
|---|---|
| Windows 機 (x86_64 版。いちばん多くなる見込み) | 質問する。初期の選択は Windows 風 |
| Intel Mac (x86_64 版) | 質問する。初期の選択は Mac 風 (`/sys/class/dmi/id/sys_vendor` が Apple なら Mac と判断する) |
| PPC Mac (PPC 版) | 質問しない。Mac 風で設定する |

- どの機械でも、あとから設定画面で Windows 風に変えられる
- キー操作: Mac 風は Enter で名前の変更・⌘+Delete でゴミ箱。Windows 風は Enter で開く・Delete でゴミ箱・切り取りあり
- 切り替えは自作の設定アプリ (小アプリ) で行う。設定を書き換えるだけで常駐しないので、動作は重くならない
- カラム表示は Thunar 本体に表示方式の1つとして追加する案を第一候補にする (C / GTK3。別アプリにすると Finder が2つになる)

## メニューバーと Dock の方針

MX Linux のパネルは便利だが、追加や挙動の変更に手間がかかる。SnowLinux では最初から Mac と同じ配置にしてしまい、変更も Mac と同じやり方 (設定画面のチェックボックス) でできるようにする。Xfce のパネル設定を直接いじらなくても済むようにする。

### メニューバー (上部、高さ 22px)

```
[ロゴ] [アプリ名(太字)] ファイル 編集 表示 …        [Bluetooth][Wi-Fi][音量][バッテリー] 日 22:41 [ユーザー名] [検索]
```

| 部分 | 部品 |
|---|---|
| ロゴのメニュー (このコンピュータについて / システム環境設定 / Dock ▸ / 最近使った項目 / 強制終了 / スリープ / 再起動 / システム終了 / ログアウト) | Xfce パネルのプラグインを自作 |
| アプリ名とメニュー (グローバルメニュー) | `xfce4-appmenu-plugin` + `appmenu-gtk3-module` |
| 右側の状態表示 (メニューエクストラ) | Xfce 標準のプラグイン + テーマ |
| 時計 | 書式を Mac に合わせる (曜日 + 時刻) |
| 検索 | Spotlight 役のランチャーを呼ぶボタン |

- 右側の項目は、Mac と同じように各設定画面の「メニューバーに表示」のチェックで出し入れする
- パネルの配置は `/etc/skel` の `xfce4-panel.xml` で最初から作り込む。MX の初期パネル (左の縦パネルなど) は使わない
- 注意: グローバルメニューに対応していないアプリ (GTK4 / libadwaita、一部の Electron アプリ) は、ウィンドウの中にメニューが残る

### Dock

| 項目 | 実現方法 |
|---|---|
| ガラス風の棚、起動中インジケーター | Plank + 自作テーマ |
| 左端は Finder、右端はゴミ箱 (区切り線あり) | Plank のランチャーとゴミ箱 docklet |
| 設定 (サイズ・拡大・位置・自動的に隠す) | Mac の「Dock」の設定画面を自作。裏で Plank の設定 (gsettings) を書き換える |
| ロゴのメニューの「Dock ▸」 | 拡大のオン/オフ・自動的に隠す・位置を、メニューから直接切り替える |

- Plank の 0.11.89 は 2019 年から更新が止まっているが、Debian 13 / MX 25 に入っていて安定している。困ったら fork か自作を検討する
- 見た目の目標は Leopard / Snow Leopard の 3D の Dock。奥行きのある半透明の板の上にアイコンが乗り、板にアイコンが映り込む。今の iPhone 風の平らな Dock にはしない
  - **Plank を改造する方向に決定** (Cairo-Dock は PPC には重いので使わない)
  - 板は「奥行きがありそうに見える」で十分。本物の 3D (台形の遠近) にはこだわらない
  - 優先順位 (重くなるものは削る):
    1. 起動中のアプリのインジケーター (必須。Plank の標準機能)
    2. 奥行きがありそうな板 (まずテーマのグラデーションと縁取りで作る。足りなければ描画部分 (Vala) を改造)
    3. 映り込み (できたら。なくても問題ない)
    4. 映り込みができないときは、アイコンの下に影を付ける
  - PPC の機械で試して、重いものは削る
  - 3D 風にする案 (ユーザー): 棚の左右の端を斜めに切ると、台形に見えて 3D 風になる。Plank のテーマの設定だけでは作れないので、Plank 本体 (描画部分) を改造する

### 信号機ボタン

- 赤 (閉じる)・黄 (最小化)・緑 (拡大) のジェル風のボタンを xfwm4 テーマと GTK テーマ (ヘッダーバーのアプリ用) で作る
- 左に置くとき (Mac 風): 左から 赤・黄・緑
- 右に置くとき (Windows 風): 左から 黄・緑・赤。閉じるボタンが右端に来るようにして、Windows と同じ位置で閉じられるようにする

## PPC Mac 対応

MX Linux / Ubuntu は PPC 非対応のため、2つのエディションに分ける。

```
SnowLinux
├ themes/ config/ assets/   ← 共通 (アーキテクチャに依存しないように作る)
├ x86_64 版: MX Linux ベース (ISO は MX Snapshot)
└ PPC 版:    Debian ports (powerpc / ppc64) ベース (ISO は live-build など)
```

注意点:

- Web ブラウザ: 最新の Firefox / Chrome は PPC 版がない
- 起動: Open Firmware → GRUB (ieee1275 版) の設定が必要
- 描画: 古い Radeon / GeForce 向けに、影や透過を控えた軽量テーマも用意
- メモリ: G4 で 512MB〜1GB を想定

### 既存の PPC Mac アプリの活用

- Cocoa (Objective-C) のアプリは GNUstep で移植できる可能性がある (PPC Linux でも動作)
- Finder のカラム表示風ファイルマネージャーなど、足りない部分を GNUstep で作る案
- Carbon のアプリは GNUstep 非対応 → 書き直しが必要

## Xfce で足りない部分と自作ツール

| 足りない部分 | 方針 |
|---|---|
| 最小化のスケールエフェクト | アニメーション対応の picom の設定で対応 (足りなければ xfwm4 を改造) |
| Finder のカラム表示 | Thunar を改造するか、カラム表示付きのファイルマネージャーを自作 |
| 左端のメニュー | Xfce パネルのプラグインを自作 (C / Vala) |
| 「このコンピュータについて」 | 小さな GTK アプリを自作 |
| Dock | Plank (拡大・インジケーター・ランチャー・フォルダ登録は標準機能) + 自作テーマ |

- 言語: Xfce との統合には C か Vala (GTK3)。ちょっとしたツールは Python でも可
- 自作ツールは PPC でも軽く動くことを確認する
- GNUstep のアプリは GTK と見た目が揃わないので、使うなら専用テーマが必要

## 自動起動の整理

MX Linux が自動で起動するものを、Mac にないもの・SnowLinux に不要なものは止める。方法は、`config/skel/.config/autostart/` に同名の `Hidden=true` のファイルを置く (MX 自身も同じ方法)。

止めるもの:

| 名前 | 理由 |
|---|---|
| Conky (skel) | デスクトップのシステム表示。Mac にない。常に動いて重い |
| MX Welcome (skel) | MX の案内画面。SnowLinux 用の初回ウィザードに置き換える |
| Clipman (skel) | クリップボード履歴。Mac にない |
| Cleanup Notifier | MX の掃除の通知 |
| keyboard switcher (gxkb) | 配列の切り替え表示。日本語キーボードだけなら不要。複数配列を使う人向けは設定で出す |
| xfce-superkey | Super キーでメニューを開く。Mac 風のキー割り当て (⌘) と衝突する |
| Startup-sound | MX の起動音。SnowLinux 用の起動音を自作するまで止める |
| restore-software-brightness | MX の画面の明るさの復元。ディスプレイ調整アプリ (ガンマ・ICC プロファイル) と衝突する可能性がある |
| Spice vdagent | 仮想マシン用。実機では不要 |

Xfce 以外 (GNOME・MATE など) 向けの Orca・Onboard・gnome-keyring の一部は、Xfce では動かないので触らない。Magnus は MX の初期設定が、すでに止めている。

残すもの (動作に必要、または Mac の右上の状態表示に相当):

- nm-applet (Wi-Fi)、blueman (Bluetooth)、電源管理、通知、スクリーンセーバー、設定デーモン、polkit の認証、音 (pipewire)、日本語入力 (im-launch、fcitx)
- print-applet (プリンターの状態。プリントを大事にするため)
- mx-usb-unmounter (USB の取り出し。Finder の取り出しに置き換えるまで)
- mx-updater (アップデートの通知。「ソフトウェア・アップデート」に置き換えるまで)
- ユーザーフォルダ、AT-SPI (GTK アプリが使う)

今後: 残したものも、右上の状態表示 (メニューエクストラ) として、アイコンや見た目を Mac に合わせる。
